# SING_IT

가칭 **LAST SONG!**

공연은 절대 멈추면 안 된다. 무대 위에서 터지는 사고를 뛰어다니며 해결하는 픽셀 협동 프로토타입.

> 음악에 맞춰 버튼을 누르는 게임이 아니라, **음악이 끊기지 않도록 무대를 지키는 게임**.

개발 순서는 `GAME_SPEC.md`, 비주얼 헌법은 `ART_GUIDE.md`.
스프라이트는 `tools/gen_sprites.py` 에서만 만든다.

## 실행

브라우저에서 ES module을 쓰므로 로컬 서버가 필요하다.

```powershell
.\tools\serve.ps1
```

그리고 http://localhost:8080 를 연다.

## 조작

| | P1 | P2 |
|---|---|---|
| 이동 | WASD | 화살표 |
| 집기 / 수리 | E | Enter |
| 내려놓기 | Q | Shift |
| 시작 | Space | |
| 음소거 | M | |

미니게임에서는 화살표/WASD로 조작하고 `E`로 확정한다. 케이블은 마우스 드래그도 지원한다.

## v0 범위

학교 축제 한 곡, 한 무대. 캐릭터는 1명부터. 사고 네 종류.

1. 기타 케이블 빠짐 → 케이블을 앰프에 꽂기
2. 기타 줄 끊어짐 → 백스테이지 예비 기타를 가져가 3개 줄의 장력을 맞춘 뒤 E로 고정
3. 드럼 스틱 날아감 → 떨어진 스틱을 드러머에게
4. 마이크 피드백 → 마이크를 든 채 안전 거리 게이지에 맞춰 배치

## Codex와 함께 만든 흐름

이 저장소는 Codex를 단순 자동완성 도구가 아니라, 작은 범위의 게임플레이 작업을 반복 검증하는 협업 도구로 사용한다.

1. `GAME_SPEC.md`, `POLISH_PLAN.md`, `ART_GUIDE.md`를 읽고 이번에 다룰 기능 하나를 정한다.
2. 기존 사고·입력·사운드 구조를 먼저 확인한 뒤 새 미니게임을 독립 모듈로 추가한다.
3. 320×180 정수 픽셀, 기존 팔레트, 텍스트 경고 최소화 규칙을 유지한다.
4. 문법 검사와 변경사항 검사를 실행하고, 로컬 서버에서 직접 플레이한다.
5. 확인된 변경만 커밋해 GitHub에 올린다.

최근 Codex 작업: 기타 줄 장력 조절, 마이크 피드백 위치 조절, 미니게임 전환 피드백, 사고별 난이도 차별화, 무텍스트 튜토리얼 경로를 구현했다.

GitHub Contributors에 보이는 `cursoragent` 표시는 과거 자동화 계정 집계로 남은 오류이며, 현재 게임에 반영된 Cursor 작업물은 제거했다. 이후 변경과 검증 흐름은 Codex 작업 기준으로 관리한다.

화면 캡처와 변경 기록은 [`docs/DEVELOPMENT_CAPTURE.md`](docs/DEVELOPMENT_CAPTURE.md)에 정리했다.

Unity 이식은 `GAME_SPEC.md` Phase 1부터. 한 번에 전체 게임을 만들지 않는다.
